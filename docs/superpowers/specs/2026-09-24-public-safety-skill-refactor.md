# 公益识骗与反操控 Skill 重构规格

> 历史规格：以下单 Skill 与归档方案记录当时的目标，不描述现行结构。现行运行时入口为 [`interaction-risk-analysis`](../../../skills/interaction-risk-analysis/SKILL.md) 和 [`person-deep-analysis`](../../../skills/person-deep-analysis/SKILL.md)。

## 目标

将仓库从通用人物深度分析工具，转为帮助普通人识别诈骗、社交工程、心理操控、胁迫和霸凌，并支持其依据材料自行判断、核验信息和选择下一步的公众安全 Skill。

## 用户与主要问题

主要用户是遇到可疑金钱/账号请求、亲密关系操控、情绪勒索、煤气灯式否认、职场或人际霸凌的人，也包括担心误判的旁观者。用户可能正处在羞耻、困惑、时间压力或权力不对等下；工具不得要求他们先给对方定性，才允许采取低风险的保护措施。

## 产品范围

### 主任务

1. 诈骗与社交工程：网恋/投资/杀猪盘、兼职与刷单、传销/资金盘、冒充权威、电诈、账号凭证索取、追回诈骗。
2. 关系中的操控与胁迫：情绪勒索、隔离支持网络、威胁/惩罚拒绝、煤气灯式反复否认、利用脆弱信息、冷热交替等可观察行为组合。
3. 职场与人际霸凌：反复羞辱、排斥、造谣、夺功/栽责、滥用权力、报复性管理和线上围攻；考虑事件频率、权力差、影响、制度环境和安全选项。
4. 误报控制：辨别一次冲突、正常分歧、合法核验/管理行为与重复的胁迫或利用模式；保留证据不足的结论。
5. 双重用途：拒绝生成操纵、欺骗、胁迫、诈骗或规避识别的行动方案；可改为透明且允许拒绝的沟通或受害者教育。

### 移出主产品

一般人格画像、约会对象画像、虚构角色分析、心理流派长报告不再属于默认运行时 Skill。现有版本完整移至 `archive/person-deep-analysis/` 留作历史版本与迁移参考，不由 Skills CLI 发现或默认安装。仅将其“事实/解释/未知”“替代解释”“不诊断”的方法保留为新 Skill 的证据纪律。

## 核心交互

Skill 不是只替用户宣布“这是某某操控”，而是把判断过程讲明白，并让用户有机会参与：

1. 先确认用户现在要处理的事；财务损失仍在扩大或有人身危险时，先给简短、可执行的止损/安全选择。
2. 把原话、行为、来源、时间、重复性、权力关系和影响分开记录；不要要求上传完整聊天或敏感账户资料。
3. 将风险术语作为待检验的模式假设，展示“哪些具体线索让我想到它”，而非人格诊断或确定动机。
4. 适时邀请用户指出自己最在意的线索，或说出什么会改变其判断；这不是诱导用户接受预设结论。用户不想回答时继续基于现有材料处理。
5. 同列支持线索、反面线索/合理替代解释和仍未知的信息；对于明显催款、隔离、威胁等组合不为假中立而弱化。
6. 提供能独立核验的办法和少量可选下一步，说明目的、风险和可逆性；低风险保护措施无需先确定对方动机。
7. 结尾让用户自行总结当前把握或选择先做哪一步；允许“还不能确定，但我暂缓转账/寻求支持”等结论。

## 结果与安全边界

- 评价行为模式与风险，不诊断 NPD、黑暗三联征等，不推断犯罪倾向、绝对动机或未来危险等级。
- 区分低/中/高风险线索的理由，不输出虚假概率或机械总分。
- 急迫资金风险优先建议暂停新增付款、拒绝交出密码/验证码/私钥、从独立找到的官方渠道核验；不承诺追回。
- 迫近的人身危险优先确认当前安全与安全使用设备，不要求独自对质或收集证据。
- 职场/霸凌建议考虑用户所在制度、报复风险和现实依赖关系，不默认举报、辞职、曝光或联系某人。
- 用户的体验值得认真对待；同理心不等于无条件确认对方恶意。判断信号可能不全，也不要求用户证明自己有资格保护边界。
- 建议应温和、具体、可撤回，不使用羞辱、居高临下或看起来像报告模板的措辞。

## 目录与接口

- 唯一可安装运行时包：`skills/scam-and-manipulation-support/`。
- `SKILL.md` 是精简入口与路由；场景细则分别放在 `references/`，按诈骗、关系操控、职场霸凌、共同推理与安全需求加载。
- 仓库级 `evals/` 保存合成输入、逐项通过/禁止标准与实测记录，不随 Skill 安装。
- `archive/person-deep-analysis/` 保存原包，不作为 `skills/` 子目录。
- 公开 README 清楚说明用途、安装口令、限制、演示案例和评估范围。远端 GitHub 仓库 slug 暂保持不变，避免在未选定品牌名时改动外部 URL。

## 验收标准

1. Skills CLI 只发现 `scam-and-manipulation-support` 一个可安装 Skill；Codex 和 Claude Code 临时安装都含齐运行时引用、不含仓库级 evals/docs/scripts。
2. 入口每次执行共享推理流程，并按场景读取一个或多个明确路由参考；运行时不得引用已归档路径。
3. 至少 20 个合成场景覆盖诈骗、胁迫/情绪操控、霸凌、模糊冲突/误报、主体性推理、即刻安全、隐私和双重用途拒绝。
4. 每个场景有非空期望与禁止行为，报告对每例标记模拟或宿主实测结果；不把静态走查写成实测。
5. 至少 8 个代表案例在真实 Codex CLI 中显式调用新 Skill 试跑，覆盖主要风险面和最易误报的边界情形；逐例用行为标准复核并记录失败。
6. 对修改后的失败案例重跑，重要缺陷修复后至少复测受影响案例并跑完整结构/安装/场景校验。
7. 最终报告明确说明这是合成场景单次试跑，不代表反诈准确率、心理测量效度或真人受益。

## 非目标

- 不是自动文本分类器、刑侦工具、法律裁决、临床诊断或资金追回服务。
- 不承诺能发现所有骗局、操控或霸凌，也不以预测施害者人格作为识别前提。
- 本轮不更改 GitHub 仓库远端 slug、不发布新版本或 npm 包。
