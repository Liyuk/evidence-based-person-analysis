# Person Analysis × 反诈与反操控：产品与 Skill 设计

> 历史规格：以下 `person-analysis` 单 Skill 与归档方案记录当时的设计。现行运行时入口为 [`interaction-risk-analysis`](../../../skills/interaction-risk-analysis/SKILL.md) 和 [`person-deep-analysis`](../../../skills/person-deep-analysis/SKILL.md)。

## 目标

把 `person-analysis` 恢复为本项目的主要分析方法，并让它优先服务于普通人识别诈骗、操控、胁迫和霸凌。Skill 不只判断一段话“像不像骗局”，还帮助用户拆解人物在一段互动中的说法、行为、时间顺序、重复模式、回应边界的方式及可独立核验的事实。

对外仍可用直白的公益定位“防骗与反操控”；`person-analysis` 说明分析方法和项目传承，不代表进行人格诊断或背景调查。

## 成功标准

1. 唯一安装入口名为 `person-analysis`，触发描述明确说明其主要用途是分析可疑互动、诈骗/操控/霸凌风险，并保留有限人物/关系材料分析用途。
2. 默认分析显式解构材料：来源与上下文、事件/时间线、原话与可观察行为、行为序列与重复性、支持与反证、竞争解释、未知、可核验点、用户可选下一步。
3. 用户只提供单条消息或单次争执时，不虚构人物稳定特征或重复模式。可用的结论范围随材料缩小。
4. 对投资/兼职/冒充/凭证索取/追回诈骗等场景，先处理迫近的资金和账户风险，再使用独立官方渠道核验身份、平台或交易。用户不必先接受“对方就是骗子”才能停止付款。
5. 心理学视角帮助解释互动机制，不作为犯罪身份、诊断或动机证据；反向操控、诱骗、报复和规避识别请求应转向透明、尊重同意的做法。
6. 现有旧版方法资产（M1–M5、启发式、关系互动、steelman、多视角及安全边界）保留为渐进读取的参考；与主要公众安全目标无关的材料不得挤占每次默认上下文。
7. 添加独立的合成验收案例，能区分拆解过程是否真实发生，而不只看是否出现“诈骗/操控”标签；运行宿主行为试跑并逐项记录。
8. README、安装脚本、技能发现、CI、竞品研究和验收报告使用一致的 Skill ID 和项目叙事。

## 核心分析流程

### 人物与互动解构

1. 明确用户要理解的人、关系或事件，以及材料的来源、说话人、时间、片段是否完整。
2. 将案例拆成事件单元：对方说了什么/做了什么；用户如何回应；之后发生什么；有何实际影响。
3. 按时间排序重要承诺、身份/故事变化、推动付款或保密的行为、用户核验/拒绝后的反应及后续要求。
4. 分开陈述直接观察、转述、解释和待证事实。只有多次可比较事件才称为重复模式；不从一条消息推出稳定人格。
5. 对主要假设说明支持证据、反证/合理替代解释、未知、改变判断的关键材料。用户纠正信息时更新分析，不维护旧判断。
6. 把人物心理理解与风险决定分开：动机可能未知，但行为的现实影响与低成本保护可以仍然讨论。

### 反诈与反操控优先路由

遇到资金、凭证、人身安全等迫近风险时，先给直接止损或求助步骤，再展开人物/互动分析。结合事件序列与具体风险类型：例如信任建立 → 移出公开平台/保密 → 时间压力 → 付款或凭证请求 → 独立核验受阻 → 追加付款/惩罚拒绝。仅将实际出现的环节列入分析，不补齐典型骗局模板。

需要核验时，将可核验主张（身份、机构、投资平台、职位、付款路径、监管/牌照等）列出，并建议用户独立打开官方来源或通过已知联系方式回拨。无实时网络/工具时，不声称已核验。不给追赃保证，不建议用户套话、钓鱼、对质或追踪嫌疑人。

面对关系操控和霸凌，分析行为、重复性、权力差、边界及后果；不要求先诊断或定性。情绪勒索、自伤威胁、监控、报复或暴力风险转入安全步骤。

## 上下文结构

- **常驻入口**：短而明确的触发范围、解构流程、安全优先原则和按需读取路由。
- **解构方法参考**：恢复旧版 M1–M5、启发式和互动分析中与观察、时间线、关系模式、竞争解释、steelman 相符的内容，并重新按当前目标整理。
- **公众安全场景参考**：诈骗/社交工程、亲密关系胁迫、职场/社交霸凌和安全/主体性步骤。
- **可选理论镜头**：CBT、人本/需求、发展、心理动力、法证证据边界和 dark-triad 行为讨论只在相关或用户要求时加载；不得增加诊断或犯罪预测主张。
- **归档**：旧版原始材料保存在 archive，供追溯；主 Skill 的实际引用不得越出安装目录。

## 验收办法

- 结构：官方 skill-creator quick validator、仓库结构/链接、场景 schema、恰好一个 CLI 可发现 Skill、Codex 与 Claude Code 隔离安装。
- 行为：至少 12 个合成宿主场景，重点评分解构完整度、风险/证据区分、反证更新、正常冲突误报边界、隐私、主体性和止损优先级。
- 记录：为每个场景列预期项、禁忌项、实际观察与 pass/partial/fail；任何关键禁止项触发即不得记为通过。失败应导致窄范围规则/参考修正并重测原场景。
- 结论限制：单模型合成场景不证明真实识骗率、心理效度、普遍可用性或受益；未跑过的案例明确列为未验收。
