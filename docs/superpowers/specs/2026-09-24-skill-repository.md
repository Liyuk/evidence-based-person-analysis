# 人际深度解析 Skill 仓库改造规格

## 目标

将现有 `person-deep-analysis` 内容整理为仓库根目录下可发现、可安装、可维护的单一 Agent Skill 仓库，并保留其“单人画像优先、关系与叙事按需扩展”的方法特色。

## 现状与约束

- 当前可见的工作区没有 Git 元数据；整理时不做提交、发布或远端操作。
- 已有主入口、8 条公理、5 个分析模块、2 个 DLC、3 份参考资料和 2 个案例 eval。
- 已完成 GitHub 对照研究，整理后文档位于 `docs/research/github-comparable-projects.md`。
- 不添加运行时依赖、自动记忆、诊断能力或未经证实的心理学背书。
- 原有结论示例中可能存在由单条信号推导创伤史、依恋类型和动机过度确定的问题；整理时要加入证据强度与替代解释约束。

## 目标用户与使用方式

使用 Agent Skills 兼容宿主的用户，将此仓库作为单一 skill 安装或复制；提供人物自述、社交文案、行为片段或关系互动材料，按材料充分度获得有证据标注的结构化分析。

## 设计

### 仓库入口

- 仓库根目录放置 `SKILL.md`，作为唯一规范入口，并保留现有 `name: person-deep-analysis`。
- 根目录 `README.md` 面向仓库访问者，说明定位、适用边界、安装/调用、输入和输出示例、方法局限及目录索引。
- `agents/openai.yaml` 提供 Codex/ChatGPT skill 元数据和展示信息。
- 不新增许可证文件，避免替用户决定授权条款。

### 目录职责

```text
.
├── SKILL.md
├── README.md
├── agents/
│   └── openai.yaml
├── modules/                 # M1–M5 分析模块
├── dlc/                     # 可选的关系动力、叙事身份扩展
├── references/              # 公理、信号映射、依恋、方法边界与安全约束
├── evals/
│   └── cases/               # 案例输入、参考输出与评估要点
├── scripts/
│   └── validate_skill.py    # 轻量静态结构/引用检查
└── docs/
    ├── research/            # GitHub 对照研究
    └── superpowers/specs/   # 本次设计规格
```

### 分析流程与输出契约

- 将 8 条公理描述为“假设生成启发式”，避免等号式因果陈述。
- 分析优先呈现可观察材料及来源，再给出假设；每个重点假设包含支持证据、至少一种合理替代解释和不确定性说明。
- 当输入过少、关键上下文缺失或竞争假设无法区分时，主动降低结论范围或提出少量澄清问题。
- 单方材料分析多人互动时，只描述可观察互动及暂定循环，不把缺席方描述为已确认的人格事实。
- 创伤、依恋和风险预测一律使用明确的可能性语言；不推断临床诊断、不虚构具体经历。
- 遇到自伤、暴力、胁迫、跟踪等风险时，暂停普通画像流程，优先回应现实安全需求。
- 默认不保存用户或第三方的输入材料，不新增记忆流程。

### 评估与维护

- 将现有两个案例收进 `evals/cases/`，保留输入、参考分析和现有检查项；同步调整过度确定的断言，使案例与证据标准一致。
- 增加 `scripts/validate_skill.py`，检查 frontmatter、必需目录/文件、相对链接和引用目标是否存在；避免额外依赖。
- README 记录验证脚本的运行方式和检查范围。该脚本仅验证仓库结构与引用，不声称验证心理结论正确性。
- 研究笔记保留在 `docs/research/`，引用来自对照仓库本身的 GitHub 页面。

## 不在范围内

- 完整心理学/临床理论综述或实证有效性主张。
- 自动抓取社交媒体、解析聊天导出、持久化记忆、GUI、CLI 或在线服务。
- 许可证选择、发布到市场、创建 GitHub 仓库或推送远端。
- 改变项目核心定位为约会决策、伴侣咨询或人格诊断工具。

## 验收标准

1. skill 主入口位于仓库根目录，内部引用均指向整理后的有效路径。
2. README 能让新用户了解用途、安装/调用方法、局限和输入输出示例。
3. 元数据文件与 skill 名称保持一致。
4. 8 条启发式、输出契约和安全边界表达一致，不把假设写成事实。
5. 两个案例可用于复核证据引用、信息不足时的克制、替代解释和不确定性表达。
6. 校验脚本可在标准 Python 环境运行且不需要第三方依赖。
7. 研究报告和规格保存在仓库 `docs/` 下，目录职责清楚。
