# 发布与采用计划

## 目标

验证目标用户能否看懂、发现、安装并完成第一次有边界的风险梳理。不要以“出圈”作为可控承诺；用实际安装与完成体验来判断传播是否有效。

可直接改写发布的项目介绍见 [Blog 项目模块](blog-project-module.md)。发布前需检查仓库地址、宿主兼容范围和评估状态，避免把合成示例写成真实用户案例或把结构校验写成准确率证明。

## 发布前清单

- [x] 加入 MIT 许可证；版权名使用本机已配置 Git 作者名 `Liyuk`。
- [x] 创建公开 GitHub 仓库并更新中英文 README 的安装地址：<https://github.com/Liyuk/interaction-risk-analysis>。
- [x] CI、skill 结构校验与 Skills CLI 本地发现及隔离安装检查通过；Codex CLI 显式调用烟雾测试已记录。测试范围不代表自动加载或相对效果。
- [ ] 检查 skills.sh/Skills CLI 的仓库索引状态和展示内容。
- [x] 准备八个明确标记为合成的场景演示；引用政府/专业机构一手来源，不使用真实私聊、照片或账号。见[演示目录](../demos/README.md)。
- [ ] 发布版本号与变更说明；对外明确启发式不是验证过的心理测量工具。

## 轻量 30 天节奏

| 阶段 | 行动 | 观察结果 |
|---|---|---|
| 第 1 周：可发现 | 发布仓库，核对索引、安装命令、默认展示名和中英文入口 | 是否能找到、能否成功安装 |
| 第 2 周：可理解 | 发一篇合成案例演示：同一条材料中什么是观察、什么是假设、哪些仍未知 | 读者是否理解边界；卡在哪一步 |
| 第 3 周：可试用 | 邀请少量目标用户用公开合成案例试跑；征求自愿反馈 | 首次成功率、耗时、输出可读性 |
| 第 4 周：可改进 | 汇总重复反馈，修订文档或规则；公布版本变更和已知限制 | 安装转化、完成率、有效问题与越界反馈 |

## 指标

优先跟踪漏斗而不是单一浏览量：仓库访问 → 安装说明点击/复制 → 安装成功 → 首次分析完成 → 用户自愿反馈。若平台不能提供安装数据，不推算或虚构；用匿名问卷/issue 记录自愿反馈。质量信号包括：证据是否能回指、低信息输入是否克制、替代解释是否有用、用户是否误认为诊断，以及安全/隐私投诉。反馈不应用来推断个人心理状态。

## 渠道顺序

1. 可复现的 GitHub 仓库和安装入口。
2. Skills CLI / skills.sh 等 skill 发现目录（先验证其索引规则和内容展示）。
3. 中文 Agent、效率工具和提示词社区：短演示配一条实际安装方式。
4. 根据问题与自愿反馈迭代，再发布新版本。

远端仓库已公开；本计划提供发布素材和节奏，不代表已向社区发帖或联系任何人。传播模板见 [content-kit.md](content-kit.md)。
