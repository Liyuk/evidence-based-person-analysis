# 互动风险识别与解构：看证据，不替人定性

> 项目介绍草稿，可用于博客或开源项目页面。例子均为合成文本；评估结果只代表有限的模型试跑。

遇到可疑转账、情绪勒索或职场霸凌时，人常常先问：“是不是我想多了？”“他到底是不是 NPD？”“我是不是太蠢才会被骗？”这类问题很容易把注意力带到给人定性，反而漏掉眼前可核对的行为：有没有被催着付款、能不能独立核实、拒绝之后发生了什么、类似事件是否反复出现。

**互动风险识别与解构**是一个可安装的 Agent Skill，覆盖网恋诈骗、其他诈骗、情绪操控与虐待、胁迫，以及职场和人际霸凌。它从人物/互动分析方法发展而来，但不试图判断“这个人是什么类型”；它让用户看见行为证据、可能解释、未知和可核实的下一步。

## 用一套方法解构，而不只接收模型结论

模型本身已经会识别许多熟悉模式；问题是它可能直接给出“这是操控/骗局”，却没说明材料如何支持这个判断。这个 Skill 用提示流程要求它先解构，再谈解释。

假设有人说：“别问那么多，信我就把钱转过来。”你提出先核实公司，对方又说：“不转就是不爱我。”Skill 会先拆出催款、阻止独立核实、把付款与感情绑定这些行为；接着解释它们怎样压缩考虑和拒绝的空间，再提出“可能在回避核验”等有限目的假设，并列出“也可能把核验误解为不信任”等替代解释。效果值得重视，但效果本身不能证明对方的主观意图。

用户可以暂停转账、通过自己找到的官方渠道核验，也可以先不作最终判断。若用户愿意，Skill 会问哪条线索最让他不安、什么证据会改变判断；如果他只想知道先做什么，或风险正在发生，就不拿追问拖延止损。

这不是“用问题诱导人相信 AI”。问题允许回答“我不确定”“那条线索可能有别的解释”，也允许用户不回答。**不确定对方动机，不妨碍一个人先保护自己的钱、边界和安全。**

## 既能识别，也要避免误报

只有一次记忆分歧，不自动等于煤气灯；一次具体、私下且有改进支持的工作反馈，不自动等于霸凌；一张收款账号变更的发票值得核实，但材料不足时不应直接判成诈骗。相反，反复催款、隔离朋友、威胁隐私、公开羞辱或提出异议后遭报复，也不该因为“也许只是玩笑”就被轻轻带过。

Skill 因此把原话、行为、来源、重复性、权力差、影响和反面信息分开处理。它不诊断 NPD 或“黑暗人格”，不按文本预测犯罪，也不要求受影响者先证明恶意才能暂停付款、拒绝要求或求助。

## 为什么做成 Skill

安装后，用户可以把 Skill 带到自己的 AI 助手里，用自然语言描述问题或提供去标识后的少量摘录。项目先按时间拆解说法、行为、回应和后果，再检查重复模式、竞争解释、反证与未知；诈骗、关系胁迫、职场霸凌和安全支持按需读取。测试和研究留在仓库，不混进运行时内容。

这让同一个判断纪律可以跨场景使用：**具体证据先于标签，行为效果与主观目的分开，因果假设可以检验和修正，决定权仍属于当事人。**

## 当前验证到哪里

当前版本维护 20 个合成验收场景，定义事件拆解、因果/目的推断、模式区分、反证更新、误报边界和安全支持的预期行为；**这些场景尚未使用改名后的 `interaction-risk-analysis` 逐例运行**。此外还保留先前版本的 21 个防骗场景。八种按四类平衡的合成演示展示了更名前以 `$person-analysis` 运行的普通 Codex / Skill 对照，见[演示目录](../demos/README.md)。历史宿主运行记录见[验收报告](../../evals/results/2026-09-25-person-analysis-anti-fraud-acceptance.md)，新版命名与方法试跑见[解构方法评估](../../evals/results/2026-09-25-decomposition-method-evaluation.md)。

这些检查可发现流程遗漏，不能证明真实世界的识别准确率、心理测量效度或真人受益。之后仍需要不同模型的重复试跑、独立人工盲评，以及经过同意、保护隐私的可用性反馈。项目不会把模拟结果包装成临床或防诈效果保证。
