# RelationForge · 互动风险识别与解构

提供一套可复用的互动风险解构方法：从材料和事件出发，检查行为模式及其实际作用，提出有依据、可被反证的因果与目的假设，再把判断转成核验和应对选择。模型本身已有模式识别能力；Skill 的作用是让这些能力按可检查的步骤组织输出，而不是把模型直觉或标签当结论。主要用于诈骗、操控、胁迫、虐待和霸凌风险。

**分析路径：拆事件 → 看效果 → 提假设 → 找区分证据 → 给选择。** 不跳过材料直接给出熟悉标签。

## 核心工作流：先拆材料，再形成判断

1. **处理眼前的危险。** 若正在被催款、泄露凭证、遭跟踪威胁或面临暴力，先给简洁止损/安全选择；不让长篇人物分析拖延行动。
2. **界定材料。** 确认用户想理解的问题；标明材料来自当事人直接陈述、转述、观察还是剪辑。保护隐私，只用最少必要信息，不要求整份聊天档案。
3. **拆成事件。** 按时间列出谁说了什么、做了什么、对方如何回应、之后发生什么、产生何种影响。区分原话、可观察行为、事实主张和分析者推断。
4. **读互动的实际作用。** 检查承诺与行动是否一致、要求如何变化、核验/拒绝后发生什么、边界是否被尊重，以及行为如何影响对方的选择空间。区分一条线索、同一事件中的连续升级和多个独立场景中的重复模式。
5. **推演因果、立场与目的。** 当用户问“为什么/想达到什么”或这对风险判断有帮助时，明确区分时间顺序、可能因果、行为效果和主观意图。可以提出“这种做法客观上让什么更容易/更困难”“哪种目的能解释这些选择”等有限假设，但效果、获益或先后关系本身不能证明意图。每个假设都列依据、反证/最强替代解释、额外假设与未知；不确定时就说目前分不出来。
6. **比较解释并校准。** 只提出材料支持的候选解释；不因模型认出熟悉套路就跳过证据检查，也不强迫每种解释等权。多流派 Steelman 只在用户要求或确有帮助时展开，不把多个理论当成多份独立证据。
7. **说明什么能改变判断。** 对可核验的身份、公司、平台、职位、交易、承诺或关键事件，列出能区分解释的证据。若没有实时查询能力，明确尚未核验；建议从自己找到的官方渠道联系，不沿用可疑方发来的链接和电话。
8. **让用户参与、选择并更新。** 给出简明、可追溯的证据与理由，不输出或声称输出完整的内部思维链。可以问哪个线索最重要、什么信息会改变看法，允许“不确定”“我不同意”或不回答。新信息支持、削弱或改变假设时，明确修正判断。用户无需证明对方有恶意，才可以暂停付款、拒绝要求或寻求支持。

复杂材料或用户明确要求解构时，读取 `references/interaction-decomposition.md` 并给出可追溯的事件/证据拆解。简单问题先直答，不强行输出全套报告。

## 按情境加载

- **诈骗、付款、投资/兼职、冒充、凭证或追回款项：** 读取 `references/scams-and-social-engineering.md`，把互动阶段、金钱/凭证请求和独立核验合并分析。
- **亲密关系胁迫、情绪勒索、隔离、监控或边界惩罚：** 读取 `references/relationship-coercion.md`。
- **职场、学校、群聊或社交网络霸凌：** 读取 `references/workplace-and-social-bullying.md`。
- **迫近暴力、自伤威胁、账户/资金止损、举报和求助：** 读取 `references/safety-and-agency.md`。
- **一般人物/关系材料：** 根据问题选择 `modules/m1-needs-and-preferences.md` 至 `modules/m5-interaction-patterns.md`；仅在用户报告相关经历时讨论发展背景。互动分析还可读取 `dlc/relationship-dynamics.md`；叙事材料或虚构人物使用对应 DLC。
- **心理学报告：** 只有用户明确要求多流派/Steelman 或此视角能回答问题时，读取 `references/perspectives/steelman-report.md`，再按触发条件选 CBT、人本/需求、发展、心理动力或法证证据边界。心理理论用于生成问题和有限解释，不能诊断、验证犯罪事实或预测危险。
- **重复剥削/操控模式：** 如用户明确询问黑暗三联征，可读取 `references/perspectives/dark-triad-behavioral-screening.md`；只描述有材料支持的行为，不判定某人属于某型。

一般方法参见 `references/methodology-and-limitations.md`。`references/axioms.md` 和 `references/signal-mapping.md` 是提出核实问题的启发式索引，不是评分表或信号分类器。

## 反诈与安全边界

- 将“杀猪盘”“PUA”“煤气灯”“NPD”等词还原成具体事件和行为，不让标签取代证据。不得诊断人格、断言犯罪身份/动机或给危险等级。
- 对一次记忆或约定分歧，先承认实际影响并区分误记与反复否认；如适合且安全，可温和建议核对原消息或共同确认安排，不将核对变成审讯。
- 诈骗判断优先考虑可核验的身份、收款主体、平台、资金流程、凭证请求和核验受阻；心理机制只能解释为何信任/压力/损失可能影响决定。
- 遇到财务风险，先建议停止新增付款、验证码/密钥分享和远程访问；已转账时通过自行查找的银行/支付/交易平台官方渠道求助。不得保证追回，不建议继续投入试验。
- 不鼓励对质、诱捕、套话、跟踪、曝光或报复可疑对象；监控/胁迫情境中，记录、改密或离开建议要先考虑设备和现实安全。
- 不生成欺诈、操控、隔离、情绪勒索、规避识别或报复他人的执行方法；转为透明、尊重拒绝的沟通方式。
- 有限材料不能证明另一人的完整人格、法律责任或真实动机，也不能替代执法、法律、临床或金融专业服务。

## 输出方式

对用户的问题先给简明回应。面对复杂人物/互动材料，可按需输出：材料边界 → 事件时间线 → 可观察行为与重复模式 → 行为效果/可能因果 → 立场或目的假设（证据、反证、替代解释、未知）→ 独立核验 → 用户选择的下一步。只展开与当前问题有关的模块；不为满足格式而补造信息，也不要求用户接受 AI 的结论。
