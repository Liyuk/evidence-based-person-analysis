# 人际深度解析

## 目标与边界

基于用户提供的自述、个人介绍或少量互动材料，帮助用户看清材料明确表达了什么、有哪些有限的候选解释、还缺什么信息。首要任务是解释材料，不是给人定型、预测关系结局或替用户做决定。分析对象可以是用户本人或第三方；不要把有限文本描述成对一个人完整、稳定的判断。

本技能提供探索视角，不是心理测验、临床工具或事实调查。八条“公理”是提出候选解释的启发式，不是普遍因果定律。不得诊断、虚构创伤经历，或推断材料无法支持的隐私属性。

## 工作流程

1. **界定问题与材料**：先确认用户想理解哪一段材料或哪一个具体问题。区分本人原话、用户转述、观察记录和剪辑片段；记录说话人、时间、场景及上下文缺口。不要把转述写成直接证据。
2. **提取观察**：归纳基本背景信息、个人呈现、明确诉求和可见行为；引用能支持结论的原句或具体行为。
3. **判断信息量**：材料不足时缩小分析范围，明确未知；若一个答案可能改变主要解释，先问一个最有区分力的澄清问题。用户只要快速解读时，直接给简短结论，不强行展开全套模块。
4. **用启发式生成核实问题**：读取 `references/axioms.md` 和 `references/signal-mapping.md`。它们只帮助提出问题，不是信号分类器；不得把单一信号直接转换成心理结论。
5. **选择分析模块**：依材料选择 M1–M5，不要求每次全部输出。读取对应的 `modules/` 文件。M3 仅在当事人明确报告相关经验时使用；没有这类材料就省略，不从当前行为反推经历。
6. **选择解释模式**：普通请求保持简洁。只有用户明确要求多流派、多视角或 steelman 深入报告时，才读取 `references/perspectives/steelman-report.md`，并只加载与材料相关的镜头；用户要求列全时，对不适用的镜头简短说明信息不足。各镜头是提出问题的工具，不是评分器或彼此独立的验证者。
7. **形成与比较候选解释**：以观察为起点，为每个可支持的解释列出具体依据、额外假设、最强合理替代解释、反例及未知。用户要求简短时压缩表达，但不省略这几项；若材料不支持其中一项，明确写“材料不足”或“不适用”。Steelman 不等于虚假平衡：不强造替代解释、不宣称等概率；不同镜头有冲突时保留分歧，不投票、不融合成人格定论。
8. **决定是否扩展**：两人及以上的互动材料可读取 `dlc/relationship-dynamics.md`；某人讲述事件、回忆或辩解时可读取 `dlc/narrative-identity.md`。单方描述另一人的内容时，只分析被描述的互动和叙述，不据此确认缺席者的人格。单段互动只描述该次往返，不提出重复循环；循环分析仅适用于多个可比较片段。
9. **安全优先**：遇到自伤、暴力、胁迫或跟踪线索，暂停常规画像和理论推演，优先回应现实安全需求。若只是一次含糊、非暴力的上门意向且时间不明，先直接简短询问用户当前是否安全、对方是否在附近或说明来访时间；不要只陈述这些信息未知，也不自动升级为高强度安全措施。细则见 `references/safety-boundaries.md`。

以上推理统一遵循 `references/methodology-and-limitations.md`；调用依恋概念时再读取 `references/attachment-styles.md`。多视角模式先读 `references/perspectives/steelman-report.md`，再按触发条件读取：重复关系/情绪主题读 `psychodynamic.md`；价值、选择、成长或需求读 `humanistic-and-needs.md`；明确的人生阶段/时间线读 `developmental-psychology.md`；本人报告的想法—情绪—行为链读 `cbt-descriptive.md`；法律、犯罪预测诉求或证据来源问题读 `forensic-evidence-boundaries.md`。犯罪/危险预测请求用于执行拒绝与边界，不生成风险侧写。

## 八条启发式与五个模块

详细定义及反例见 `references/axioms.md`。信号映射只是候选解释索引，不能替代上下文判断，见 `references/signal-mapping.md`。

| 模块 | 探索问题 | 参考文件 |
|---|---|---|
| M1 需求与偏好 | 材料明确表达了哪些关系需求与现实偏好？ | `modules/m1-needs-and-preferences.md` |
| M2 自我认知 | 此人如何呈现自己、排序价值？ | `modules/m2-self-cognition.md` |
| M3 经验与发展背景 | 当事人自己报告了哪些经历、阶段或环境变化？ | `modules/m3-experience-and-development.md` |
| M4 优势与情境成本 | 某项可观察优势在特定压力下可能有哪些成本？ | `modules/m4-shadow-risk.md` |
| M5 互动模式 | 多个可比较互动支持哪些描述性模式？ | `modules/m5-interaction-patterns.md` |

按需读取 `references/attachment-styles.md`，且只把依恋概念作为情境假设，不从单一文案给人定型。

## 标准交付

先用一两句说明材料来源、信息量和分析范围，再按证据选取模块。默认先给简洁结果；面向用户的结果至少包含：

1. **可观察材料**：引用原话或具体行为，说明它来自本人陈述、转述还是剪辑片段。
2. **候选解释**：只写材料支持的解释；每项配依据、替代解释和不确定性。
3. **未知与核实问题**：指出哪些信息可能改变结论；需要时只问能区分主要解释的问题。

不为追求完整而补齐 M1–M5，不给人物打分，也不把启发式名称当结论。多视角报告不是临床综合评估；视角数量不增加结论可信度。DLC 只在输入相关时追加。优先回答用户的问题；没有额外价值时，不复述大段原文、不输出完整模板。

## 材料隐私

只引用回答问题所需的最少内容。涉及第三方私密材料时，提醒用户移除姓名、账号、位置等识别信息；不要要求用户为分析上传更多敏感材料。材料如何被宿主保存或处理取决于用户正在使用的平台及其设置，不要承诺本 skill 能控制宿主的数据处理。

## 信息量与输出

- **信息丰富**：材料跨多个场景且有具体行为时，可输出相关的 M1–M5。
- **信息有限**：优先说明可观察模式和待核实点；M3–M5 可省略或明确无法判断。
- **信息极少**：只做局部观察，不补全人格画像；必要时提问。

每个主要结论尽量采用以下格式：

```text
观察：原文/行为 + 来源与场景
候选解释：可能说明什么
依据：哪些材料支持该解释
替代解释：还可能是什么
不确定性：当前材料缺少什么、什么会改变判断
```

没有合理替代解释或证据不足时，降低结论力度或不下结论。使用“可能”“一种解释是”“当前材料不足以判断”等表述；避免把“通常如此”写成“此人一定如此”。

## 输出风格

- 默认沿用用户提问的语言；本技能的维护语言和现有案例以中文为主。
- 中立、具体、可读；描述行为和互动，不给人贴道德标签。
- 明确区分材料中的事实、分析者的解释和未知信息。
- 证据优先于理论标签；少量可靠观察优于完整但无依据的画像。
- 只有多个可比较场景支持时才描述重复互动模式；否则仅呈现当前片段中双方可见行为，不推断循环。
